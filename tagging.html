Version tagging ​

The reusable bump-version-tag.yml workflow validates the supplied commit header, determines a semantic-version increment from its prefix, then creates and pushes an annotated tag pointing at the caller's github.sha.

Call the tagger ​

The caller must grant contents: write so the workflow can push the tag. The repository's Actions settings must also allow the GITHUB_TOKEN to write repository contents.

yaml
name: Tag release

on:
  push:

permissions:
  contents: write

jobs:
  tag:
    uses: ssongin/gha-commit/.github/workflows/bump-version-tag.yml@master
    with:
      commit_message: ${{ github.event.head_commit.message }}

Pin the reusable workflow to a reviewed release tag or full commit SHA instead of @master for production use.

Version rules ​

Prefix or markerResult
epic, majorMajor
featMinor
fix, build, chore, perf, refactor, revert, style, cicdPatch
docs, testNo tag
chore(release)No tag
! after the type/scope, or a BREAKING CHANGE: / BREAKING-CHANGE: lineMajor

A breaking change takes precedence over the prefix's normal bump. Use ! immediately before the colon:

text
feat(api)!: remove the legacy endpoint

Alternatively, include a breaking-change footer on its own line after the header and body:

text
feat(api): revise the response format

BREAKING CHANGE: clients must now read the result field

Both examples trigger a major bump. docs!: and test!: are also major bumps; without a breaking-change marker, docs and test commits do not create a tag. The chore(release) exception skips version-bump commits generated by a release process.

The workflow uses the highest existing tag matching the prefix and MAJOR.MINOR.PATCH format. Tags use v by default (for example, v1.2.3). If no matching tag exists, the default baseline is 0.0.0; therefore the first feat produces v0.1.0, and the first fix produces v0.0.1.

Optional inputs ​

InputRequiredDefaultDescription
commit_messageYes—Message used to validate and choose the increment
tag_prefixNovPrefix used to find and create version tags
initial_versionNo0.0.0Baseline semantic version if no matching tag exists; do not include the prefix

For example, to create release-1.0.1 after a patch change when no matching tag exists:

yaml
jobs:
  tag:
    permissions:
      contents: write
    uses: ssongin/gha-commit/.github/workflows/bump-version-tag.yml@master
    with:
      commit_message: ${{ github.event.head_commit.message }}
      tag_prefix: release-
      initial_version: 1.0.0

To run validation and tagging in the same caller workflow, add needs: validate to the tag job. The workflows can also be called independently.
