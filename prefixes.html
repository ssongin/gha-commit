Allowed commit prefixes ​

Use one of these lowercase prefixes at the start of each commit message. These are the prefixes accepted by gha-commit's validator and supported by its tagging workflow.

PrefixPurposeVersion bump
epicLarge product milestone or coordinated feature setMajor
majorExplicitly mark a major release changeMajor
featAdd or extend user-visible functionalityMinor
fixCorrect a bugPatch
buildChange build system, dependencies, or packagingPatch
choreRoutine maintenance that does not change product behaviorPatch
perfImprove performancePatch
refactorRestructure code without changing behaviorPatch
revertRevert a previous changePatch
styleFormatting or style-only changePatch
cicdChange CI/CD workflows or deployment configurationPatch
docsDocumentation-only changeNo tag
testAdd or update testsNo tag

The tagger also skips chore(release) commits, which are commonly generated by release automation. A breaking-change marker overrides the normal bump: append ! after the prefix or scope to request a major bump. For example, fix(api)!: change the error response is a major change despite the fix prefix. See Bump version tag for footer syntax and details.

Header examples ​

The scope is optional, but when present it must not be empty:

text
feat: add keyboard navigation
fix(router): preserve query parameters
build(deps)!: drop support for the old runtime

The third example creates a major bump because it includes !. A breaking change can also be declared with a BREAKING CHANGE: or BREAKING-CHANGE: footer; those footer forms are described in the version tagging guide.
